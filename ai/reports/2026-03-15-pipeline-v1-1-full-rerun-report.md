## 6. v1.1 Rerun Verdict

### v1.1 是否比 v1 更接近可上稿 workflow？

**部分是。**

### 最關鍵改善的 3 點

1. **legacy 三分模型正確分流。** `protected_phrase`（100天安心睡）確實只保護 phrase coverage，未造成 blanket retain。`must_include_token`（山丘樂眠床、LOVEFU、飄雲專利）正確地不構成 retain 理由——sh-15 類的弱句即使含 token 也能被正常 retire。`reusable_motif` 僅作為 pattern guidance，未被誤判為 hard gate。

2. **decision_basis / decision_confidence 全面填入。** 140 則素材每則都帶完整 `decision_basis` object（含 cohort_percentiles、primary_metric、eligible_asset_count）和 `decision_confidence`。因報表缺乏 CTR，系統誠實地把所有 confidence 限制在 `low` / `directional`，未出現 v1 中虛報 `high` 的問題。

3. **field-level handoff contract 真正生效。** Builder 在啟動前逐欄驗證了 27 個 field path，Packager 驗證了 7 個 section。coverage_check 拆分為 protected_phrase_check / token_coverage_check / motif_coverage_check 三區塊，不再只是一個 must_include 布爾值。

### 仍存在的 3 個主要問題

1. **原始數據品質嚴重不足。** 報表 0 impressions / 0 clicks，只有 conversion association estimates。這讓 CTR percentile 完全無法計算，所有決策被迫退回 conversion count proxy。即使 pipeline 架構正確，輸出品質仍受限於輸入品質。**根因：Google Ads 素材關聯報表的結構限制，非 pipeline bug。**

2. **observe 素材比例過高（56%）。** 79/140 素材因 conv=0 或 conv 在 P25–P50 之間而落入 observe。這反映數據覆蓋率不足——大量素材從未獲得足夠的曝光來產生 conversion。v1.1 的決策規則忠實執行了，但結果是可操作的 retire/reinforce 決策太少。**建議：v1.2 可加入「active_duration 門檻」——素材上線超過 N 天仍無 conversion 時，降級為 retire 候選。**

3. **Candidate 數量偏低（僅 3 則）。** Interpreter 只產出 3 個 new_candidate_assets，而 Builder 需要更多候選來填補 15 則退場後的空位。**根因：Interpreter 的 candidate generation 仍依賴手動 heuristic，未接入 brief generator。v1.2 應串接 ad-copy-brief-generator 讓候選自動補充。**

### 是否建議進 v1.2？

**是。** v1.1 的 schema / contract / handoff 架構已驗證可行，但需要 v1.2 解決：

1. **輸入層升級**——串接含 impression/click 的完整素材報表（非僅 association report）
2. **observe 決策細化**——加入 active_duration 門檻，減少 observe 堆積
3. **candidate pipeline 自動化**——串接 ad-copy-brief-generator 自動產出足量候選
4. **angle_key 標準化**——建立 angle taxonomy，取代目前的 heuristic 分類
